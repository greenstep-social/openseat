# Room Occupancy & Noise Monitor

Прототип системы: подсчёт людей и относительный уровень шума в 5-10 комнатах,
данные отображаются на сайте.

## Архитектура

```
Камеры/сенсоры (RTSP / WiFi)
        │
        ▼
room_occupancy_server.py   (FastAPI + фоновые потоки-воркеры)
  ├─ camera_worker   → YOLOv8 → количество людей
  ├─ noise_worker    → ffmpeg (аудио-дорожка RTSP) → RMS → относительный dB
        │
        ▼
   occupancy.db (SQLite: occupancy_history, noise_history)
        │
        ▼
   /api/occupancy, /api/noise   (REST, читает occupancy_dashboard.html)
        │
        ▼
occupancy_dashboard.html   (карточки комнат + график истории, Chart.js)
```

Один центральный сервер тянет RTSP-потоки со всех камер (видео + опционально
аудио-дорожку) — без edge-инференса, т.к. на 5-10 комнат с редкими кадрами
(раз в 5 сек) нагрузка умеренная даже на CPU.

## Файлы проекта

| Файл | Назначение |
|---|---|
| `room_occupancy_server.py` | Backend: захват RTSP, YOLO-детекция людей, оценка шума, FastAPI, SQLite |
| `occupancy_dashboard.html` | Frontend: карточки комнат + график истории + "типичный день" |
| `esp32_cam_room_monitor.ino` | Прошивка ESP32-CAM: снимает кадр и шлёт на сервер по WiFi (альтернатива RTSP-камере) |
| `generate_test_history.py` | Генерирует синтетическую историю за 30 дней — для теста графика "типичный день" без ожидания реального месяца |
| `requirements.txt` | Python-зависимости |
| `EQUIPMENT.md` | Список оборудования и закупки |

## График "типичный день"

Помимо графика "последние N часов" (сырая история, `/api/*/history`), есть
агрегат по часу дня за последние 30 дней — `/api/occupancy/{room_id}/daily_profile`
и `/api/noise/{room_id}/daily_profile`, диапазон 8:00-22:00, с фильтром
`weekday_filter=all|weekday|weekend`. Оба подхода работают параллельно и не
заменяют друг друга: history — для "что происходит сейчас/сегодня",
daily_profile — для "как обычно бывает в это время". На дашборде — два
отдельных графика друг под другом.

**Как протестировать без месяца реальной эксплуатации**: `python generate_test_history.py`
засеет `occupancy.db` синтетическими данными за 30 дней (пик занятости к
14:00 в будни, почти пусто по выходным) — не трогай на проде, тестовые
данные не отличить от реальных задним числом. Для чистого теста лучше
временно переименовать `occupancy.db` или прогнать скрипт на копии.

## Два способа подключить камеру

**RTSP (готовая IP-камера, `CAMERAS` в коде)** — сервер сам тянет поток,
воркер описан выше.

**Push (ESP32-CAM, без RTSP)** — устройство само отправляет кадр на
`POST /api/frame/{room_id}/upload` (JPEG в теле запроса) раз в
`CAPTURE_INTERVAL_MS`, заданный в прошивке. Комната не обязана быть заранее
в `CAMERAS` — появится в `/api/rooms` сама после первого присланного кадра.
Пропиши в `esp32_cam_room_monitor.ino`:
```cpp
const char* WIFI_SSID = "...";
const char* WIFI_PASSWORD = "...";
const char* SERVER_URL = "http://IP_сервера:8000/api/frame/room_1/upload";
```
Оба способа используют одну и ту же YOLO-обработку — можно смешивать: часть
комнат на RTSP-камерах, часть на ESP32-CAM.

## Установка

```bash
# Системная зависимость (для аудио-воркера)
sudo apt install ffmpeg

# Python-зависимости
pip install -r requirements.txt
```

## Настройка

В `room_occupancy_server.py` заполнить своими адресами:

```python
CAMERAS = {
    "room_1": "rtsp://user:pass@192.168.1.101:554/stream1",
    ...
}
NOISE_CAMERAS = {
    "room_1": "rtsp://user:pass@192.168.1.101:554/stream1",  # можно тот же URL
    ...
}
ROOM_CAPACITY = {
    "room_1": 6,   # реальное число рабочих мест в комнате
    ...
}
```

Пороги категорий шума (`NOISE_QUIET_MAX`, `NOISE_MEDIUM_MAX`) — отправная
точка, метрика относительная, откалибруй по своим комнатам после недели
реальных замеров.

Для `NOISE_CAMERAS` на камере должен быть **явно включён аудио-канал**
(Configuration → Audio в веб-интерфейсе Hikvision, по умолчанию выключен).

В `occupancy_dashboard.html` поменять `BASE_URL` на адрес сервера, если не
localhost.

## API

Основной эндпоинт для карточки комнаты на сайте — `/api/rooms`: отдаёт по
каждой комнате количество людей, `occupancy_percent`, `free_spots`,
`noise_category` (`quiet`/`medium`/`loud`) и `photo_url` (последний кадр с
камеры, `/api/frame/{room_id}`). Отдельные `/api/occupancy*` и `/api/noise*`
остаются для истории и точечных запросов.

## Запуск

```bash
python room_occupancy_server.py
```

Сервер поднимется на `http://0.0.0.0:8000`. Откройте `occupancy_dashboard.html`
в браузере (или разместите на веб-сервере) — он сам начнёт опрашивать API.

## Важные ограничения текущего прототипа

- **Шум — относительная метрика**, не откалиброванный SPL в дБ. Для точных
  абсолютных значений (например, для нормативов по шуму) нужен отдельный
  калиброванный сенсор (Milesight WS302 / Tuya decibel-метр), а не встроенный
  микрофон камеры.
- **Приватность звука**: сырые аудио-сэмплы нигде не сохраняются и не
  логируются — только итоговое число раз в 5 сек. Тем не менее, включение
  аудио на камере в помещении с рабочими местами — вопрос, который стоит
  явно согласовать с людьми, работающими в комнате, до включения.
- **Одна точка отказа**: один сервер обслуживает все комнаты. Для
  некритичной аналитики (просто occupancy-дашборд) это приемлемо; если
  важна отказоустойчивость — стоит продумать резервирование.
- SQLite достаточен для 5-10 комнат при текущей частоте записи; при
  масштабировании или многолетнем хранении — перейти на PostgreSQL и
  добавить ротацию старых записей.

## Возможные следующие шаги

- Приём данных от готовых сенсоров (Tuya через `tinytuya`, или вебхуки от
  LoRaWAN-платформы типа TTN/Datacake для Milesight WS302).
- Приём кадров от ESP32-CAM по push-модели (`POST /api/frame/{room_id}`)
  вместо RTSP pull — если часть камер работает по WiFi без прямого RTSP.
- Авторизация на API, докеризация, алерты при недоступности камеры/сенсора.
