БЫСТРО ПОСМОТРЕТЬ
Открой demo.html двойным кликом. Сервер для демонстрации не нужен.
В этом режиме пять вымышленных пространств, примерные показания и демосхема.

ЗАПУСТИТЬ С ВАШИМИ ДАТЧИКАМИ
1. Скопируй рабочий .env из предыдущей версии рядом с main.py.
2. В терминале из этой папки:
   python3 -m venv .venv
   source .venv/bin/activate
   python3 -m pip install -r requirements.txt
   python3 main.py
3. Открой http://127.0.0.1:8000

index.html через сервер начинает работу в режиме «Датчики».
В нём остаётся ваша Библиотека с sensor_location=test_room.
Существующий ESP32-скетч и адрес /noise сохранены.
Неизвестные или устаревшие данные не показываются как нули.
Нет подключения? Каталог доступен, показатели отмечены как недоступные.

OpenSeat: новый дизайн с данными ESP32 + FastAPI + Supabase

ЗАПУСК (Mac, Python 3.10+)
1. Распакуй архив и открой терминал в папке OpenSeat-connected.
2. Останови предыдущий сервер: Ctrl+C в его терминале.
3. Скопируй свой рабочий .env из пилотной версии рядом с main.py.
   Скрытые файлы в Finder: Cmd+Shift+.
   Если .env нет: cp .env.example .env
   Затем открой .env и вставь SUPABASE_KEY вместо PASTE_KEY_HERE.
4. Выполни:
   python3 -m venv .venv
   source .venv/bin/activate
   python3 -m pip install -r requirements.txt
   python3 main.py
5. Открой http://127.0.0.1:8000 в браузере и включи ESP32.
   Нельзя просто открыть index.html двойным кликом: данным нужен сервер.

При повторном запуске:
   source .venv/bin/activate
   python3 main.py

ДАННЫЕ
Библиотека на сайте соответствует location=test_room в существующей noise_data.
GET /api/spaces — последнее измерение каждой точки и данные для рекомендаций.
GET /api/history?location=test_room — последние 50 записей Библиотеки, новые первыми.
GET /api/current?location=test_room — последнее измерение.
Обновление сайта каждые 5 секунд. Показаны значение, категория, время и история.
Измерение старше минуты помечается как устаревшее; ошибка подключения очищает
показания. Поиск, избранное и фильтр по тишине работают с Библиотекой.
Количество свободных мест, загруженность, этаж и часы работы неизвестны:
в интерфейсе нет придуманных значений. Фото иллюстративное.
Карта готова как раздел; схема и реальная точка ещё не добавлены.

ГРАНИЦЫ
Тихо: 0 <= значение <= 200.
Средне: 200 < значение < 500 (для целых показаний 201–499).
Громко: значение >= 500.
Это условные единицы датчика, не децибелы.
Категория старых записей пересчитывается при чтении; сохранённые старые строки
не переписываются. Новые записи сохраняются с обновлённой категорией.

ESP32
Существующий скетч менять не нужно, если IP компьютера прежний.
POST http://<IP компьютера>:8000/noise
JSON: {"location":"test_room","noise_level":123}
Если IP изменился, замени serverUrl в своём Arduino-скетче и прошей плату.
Компьютер с сервером должен работать и быть доступен плате по сети.

ПРОВЕРКА
http://127.0.0.1:8000/api/history?location=test_room
Если ошибка 503 — сообщение на сайте объяснит причину (ключ, база или сеть).
Ошибка 422 — неправильный JSON или location. Успешный POST возвращает saved.
Ключ Supabase хранится только в .env на сервере, не в HTML или JavaScript.
Шрифт Manrope с кириллицей и логотип OS включены локально.

НОВОЕ: НЕСКОЛЬКО ТОЧЕК И «КУДА ПОЙТИ СЕЙЧАС»
Вместо большой плашки Библиотеки на главной — два списка (до 3 точек):
- «Самые тихие»: по возрастанию значения шума;
- «Наименее загруженные»: по возрастанию процента занятых мест.
При равной загруженности выше точка с большим числом свободных мест.
Участвуют только показания с корректным временем, не старше 60 секунд.
Измерения с временем более чем на минуту в будущем также исключаются.
Неизвестные значения не считаются нулевыми. При отсутствии показаний
показывается объяснение. При одной подключённой точке будет одна рекомендация.
Один и тот же объект может быть в обоих списках.

КАК ДОБАВИТЬ МЕСТО
1. Открой spaces.json. Добавь объект в массив, отделив его запятой.
2. Пример объекта (также есть spaces.example.json с двумя точками):
   {
     "id": "quiet-hall",
     "name": "Тихий зал",
     "sensor_location": "quiet_hall",
     "description": "Место для самостоятельной работы.",
     "photo": "assets/quiet-hall.jpg",
     "building": "Учебный корпус",
     "floor": 2,
     "capacity": 20,
     "occupancy_enabled": false
   }
3. id и sensor_location должны быть уникальны. id: латинские маленькие буквы,
   цифры и дефис. Название и описание могут быть на русском.
   photo можно оставить "" — будет аккуратная заглушка. Если указал фото,
   положи изображение в assets. capacity и floor можно оставить null.
4. Новый датчик должен отправлять этот sensor_location:
   POST /noise {"location":"quiet_hall","noise_level":180}
5. Перезапусти python3 main.py. Каталог, карточка, поиск, избранное, списки
   рекомендаций и раздел карты подхватят новое место автоматически.
   В HTML/JavaScript добавлять копии карточек не нужно.
GET /api/spaces отдаёт метаданные и последнее измерение каждой точки отдельно.
Ошибка одного датчика не скрывает данные остальных.
Для истории используется GET /api/history?location=<sensor_location>.
Старые ссылки #space/0 на Библиотеку также продолжают работать.

КАК ПОДКЛЮЧИТЬ ЗАГРУЖЕННОСТЬ ПОЗЖЕ
Сейчас загруженность неизвестна: датчик микрофона не считает людей.
1. Когда будет источник данных занятости, выполни occupancy_setup.sql
   в Supabase SQL Editor. Таблица noise_data остаётся прежней.
2. Для нужной точки в spaces.json поставь occupancy_enabled: true.
   Если указана capacity, total в измерении должен с ней совпадать.
3. Перезапусти сервер. Источник занятости отправляет, например:
   POST /occupancy
   {"location":"quiet_hall","occupied":4,"total":20}
4. Сервер сохраняет запись, сайт показывает 20% занято и 16 свободных мест.
   Точка автоматически участвует в списке наименее загруженных.
   Ноль occupied — допустимое реальное измерение. Отсутствие записи — не ноль.
Нужен серверный ключ Supabase с доступом к occupancy_data, как для noise_data.
Пока occupancy_enabled=false, сайт не обращается к новой таблице.

Проверено на имитации ответов базы: несколько точек, независимые ошибки,
разные пороги, ранжирование, нулевая/неизвестная/устаревшая занятость.
Реальные датчики и Supabase проверяются на твоём компьютере.

КАРТА ЛЕТОВО
Раздел «Карта» содержит планы этажей 0–3 из letovo-navigator-main,
149 узлов навигации и 86 доступных пунктов назначения из переданного Levels.java.txt.
Маршрутизация перенесена в JavaScript; Java-сервер не требуется.
Выберите начало и конец из списка, затем нажмите «Построить маршрут».
На плане можно выбрать кабинет и нажать «Отсюда» / «Сюда».
Этажи маршрута отмечены точкой; лестничные переходы показаны под картой.
Масштаб: кнопки +/−, колесо; перемещение: перетаскивание или стрелки при фокусе на карте.
Карта и маршруты соответствуют исходному файлу; изменения здания после его составления не учтены.
Связь библиотеки с каталогом: узел Li (102), 3 этаж. Показания датчиков остаются на странице пространства.
Данные: assets/letovo/data.js; логика: assets/letovo/map.js; планы: assets/letovo/floor_*.png.
